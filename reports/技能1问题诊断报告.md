# MOBA 对战平台「技能1」渲染问题诊断报告

- **报告日期**：2026-09-06
- **诊断对象**：`run_battle.py` 生成的 `output/battle_*.log` 中频繁出现 `【技能1】` 而非具体技能名
- **诊断结论**：**非自动化逻辑 bug，系技能池路径配置错位（自动化/环境问题），顺带掩盖少量真正的数据缺口**
- **状态**：仅诊断，未执行任何修复

---

## 1. 结论摘要

| 维度 | 结论 |
|---|---|
| 是否逻辑 bug | 否。模拟器的「技能N」兜底是有意设计的防崩机制 |
| 根因类别 | **路径配置错位**（自动化/环境） |
| 真实数据是否损坏 | 否。62% 受影响英雄在真实技能池中存在含正确技能名的文件 |
| 真正的数据缺口 | 仅约 55 名英雄在任何来源均找不到技能（需手动补） |
| 修复影响面 | 全局（修路径会用池文件覆盖全部英雄技能），需先评估回归 |

---

## 2. 现象

最新一场实战（`output/battle_20260906_074928_1.log`）中，抽取日志内技能渲染：

```
【技能1】 出现 240 次
```

该场双方为 `[港漫群英] 刀神` 与 `[Honor of Kings] 元始天尊`，两者技能均被渲染为「技能1/技能2/技能3/技能4」而非具体名称。

---

## 3. 根因分析

### 3.1 渲染兜底机制（设计如此，非 bug）

`core/simulator.py` 中：

- `_skill_desc()`（约 196–205 行）：当技能 dict 缺 `name`/`description`，或 `skills=None` 时，返回 `f"技能{idx+1}"`
- `_skill_name()`（约 188–194 行）：dict 缺 `name` 时返回 `f"技能{idx+1}"`

该兜底保证缺技能数据的卡也能跑完对战不崩溃，属于防御性设计，**行为正确**。

### 3.2 真正的根因：技能池路径指错

| 路径 | 用途 | 状态 |
|---|---|---|
| `core/paths.py` → `SKILLS_DIR = E:\moba_battle_platform\data\skills` | loader 注入技能时查找的池目录 | **不存在 / 为空** |
| `E:\moba_battle_platform\moba_battle_platform\data\skills` | 真实已填充技能池（40 个游戏，含正确技能名） | 存在，OK |

调用链：

```
core.loader._inject_skills()
  → _resolve_skill_pool(ip_dir)  按 SKILLS_DIR 查找
  → 目录不存在 → 返回 (None, None)
  → _inject_skills 直接 return，不注入任何技能
  → 卡片自身 skills 若为 None/空 → 模拟器走「技能N」兜底
```

即：**数据本身完好，但 loader 永远找不到技能池，依赖池注入的英雄全部退化成「技能1」。**

## 5. 修复建议（未执行）

### 5.1 推荐方案

将 `core/paths.py` 的 `SKILLS_DIR` 指向真实池，或在 `core/loader.py` 的 `_resolve_skill_pool()` 中增加嵌套路径回退（当配置目录为空时回退到 `moba_battle_platform/data/skills`）。

- 预期效果：3548 名兜底英雄中 3493 名将恢复具体技能名，「技能N」应降至约 55。
- 剩余约 55 名：需在真实池中补建对应技能文件（真·数据缺口）。

### 5.2 风险与前置验证（必须先行）

1. **全局覆盖风险**：启用池注入后，会用池文件覆盖**全部**英雄技能，包括当前已正常渲染的约 2146 名（其自带技能会被池版本替换）。须先小范围比对：池文件与卡片自带技能在 `name`/`damage`/`effects` 上是否一致，评估对战斗平衡与结果的影响。
2. **池文件格式校验**：需确认 40 个游戏、全部池文件均为合法 `list[dict]` 且含 `name`，避免引入新的兜底或崩溃。
3. **回归测试**：修复后跑多场对战，确认退出码=0、日志含双段、且「技能N」占比显著下降。

### 5.3 不建议的作法

- 直接在 `simulator._skill_desc` 里把「技能N」改成别的占位文本 → 治标不治本，掩盖真实数据缺失。
- 盲目运行迁移脚本批量改写卡片 → 用户明示「切勿盲目运行迁移脚本」，应先 `tools/check_cards.py` 查验。
