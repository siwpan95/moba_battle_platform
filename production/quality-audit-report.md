## 4. 问题三：角色风格/特色缺失

### 4.1 核心发现

经过全量扫描（每 IP 抽样 5 张 + 全量技能名分类），发现两个截然不同的质量层级：

#### 层级一：技能名有 IP 辨识度（20 个 IP，690 张卡）

技能名使用了真实的 IP 来源内容（如"三刀流·鬼斩""钻心咒""磁场转动·细胞重组"），**但 100% 卡的 description 为空 + effects 为空**。

**诊断**：B 类（待优化）——技能名方向正确，但缺少风味描述和机制 effect 数据。

#### 层级二：技能名大量使用模板泛称（11 个 IP，1,129 张卡）

技能名使用跨 IP 通用的角色定位模板，如"战士·旋风斩""射手·精准射击""坦克·岩盾守护"，且 description 和 effects 均为空。

**诊断**：A 类（急需）——从技能名到描述到 effects，需要完整的风格重写。

## 6. 总工时估算与分批次计划

### 工时估算模型

| 任务类型 | 单位工时 | 适用范围 |
|----------|---------|---------|
| 文件名汉化（脚本） | 0.5h | 522 张，一键脚本 |
| 生成 description（AI 辅助） | 3-5 分钟/张 | 1,819 张，需逐张 prompt |
| 生成 effects（AI 辅助+人工校验） | 5-10 分钟/张 | 1,819 张 |
| A 类技能名改写（人工+AI） | 10-15 分钟/张 | ~1,129 张 |
| B 类技能名微调（AI 辅助） | 2-3 分钟/张 | ~690 张 |
| 新英雄设计（从零） | 1-2 小时/张 | 60-90 张 |
| 质量审查 + 一致性校验 | 1 人天/100 张 | 1,819 张 |

### 分批次执行计划

#### 第 0 批：脚本自动化（0.5 天）

| 任务 | 工具 | 产出 |
|------|------|------|
| 522 张文件名汉化 | 脚本（hero.name → 文件名） | 统一中文文件名 |
| 全量卡 description 模板生成 | AI 批处理 | 基于技能名+hero 自动生成初版 description |
| A 类 IP 技能名初版替换 | AI 批处理 | 基于 IP 知识库生成 IP 特色技能名 |

**工时**：0.5 天（脚本编写+运行）+ AI API 调用费用

#### 第 1 批：P0-A 类（11 IP × 1,129 张）— 2-3 周

**目标**：A 类 IP 的技能名完全替换为 IP 特色名称 + description + effects 初版生成

| 阶段 | 内容 | 工时估算 |
|------|------|---------|
| 技能名 AI 生成 + 人工筛选 | 每英雄 4 个技能名 | 11 IP × ~103 张 × 5min = 94h |
| description AI 生成 + 人工润色 | D&D 风格描述 | 11 IP × 5min = 94h |
| effects 设计 + 平衡校验 | 伤害/控制/位移 | 11 IP × 8min = 150h |
| IP 内一致性审查 | 同 IP 不重名、不冲突 | 11 IP × 2h = 22h |
| **小计** | | **约 360h / 9 周（1 人）** |

**并行策略**：3 人并行，每人 3-4 个 IP → **2-3 周**

#### 第 2 批：P0-B 类（20 IP × 690 张）— 1-2 周

**目标**：B 类 IP 已有 IP 特色技能名，重点补 description + effects

| 阶段 | 内容 | 工时估算 |

#### 第 3 批：P1 英雄池扩充（60-90 张新卡）— 2-3 周

| 任务 | 工时估算 |

## 7. 执行策略：批量脚本 vs 人工

### 7.1 可批量脚本化

| 任务 | 自动化程度 | 工具/方法 |
|------|-----------|----------|
| 文件名汉化（英文→中文） | ✅ **100% 可脚本** | 读 `hero.name` → 写 `os.rename()` |
| 统计扫描（文件名/技能名/description/effects） | ✅ **已完成** | `tools/batch_audit_*.py` |
| description 初稿生成 | ⚠️ **80% AI + 20% 人工** | LLM 批处理，人工抽检 |
| 模板技能名→IP 技能名初版替换 | ⚠️ **60% AI + 40% 人工** | LLM 基于 IP 知识库生成，人工审核 |
| 一致性检查（同 IP 内重名技能） | ✅ **100% 可脚本** | 正则匹配 |
| 回归测试 | ✅ **100% 可脚本** | `pytest` + `check_cards` |

### 7.2 必须逐英雄人工

| 任务 | 原因 |
|------|------|
| A 类技能名最终定稿 | 需要 IP 知识深度，AI 生成可能张冠李戴 |
| effects 数值平衡 | 涉及游戏机制和跨英雄平衡 |
| description 风味润色 | D&D 风格需要文学判断力 |
| 新英雄完整设计 | 创意决策不可自动化 |
| 跨 IP 一致性终审 | 需要全局视角 |

### 7.3 推荐工具链

```
1. batch_rename.py          → 文件名汉化（第 0 批）
2. batch_generate_desc.py   → AI 批量生成 description 初稿（第 0 批）
3. batch_skill_rewrite.py   → AI 批量替换模板技能名为 IP 特色（第 0 批）
4. check_consistency.py     → 跨卡一致性校验（持续集成）
5. check_cards + pytest     → 格式+逻辑回归（每次修改后）
```
